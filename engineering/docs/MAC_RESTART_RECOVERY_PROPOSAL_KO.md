# Mac 종료 기록 유실 복구 후보

이 절차는 소스 후보이며 User의 계약 채택 전에는 `apply`를 실행하지 않는다.
기존 앱의 UNKNOWN 해제 조건을 확장하므로 일반 설치 권한만으로 활성화하지 않는다.
`AGENTS.md` §6·8의 중요한 계약 변경 절차에 따라 정확한 변경 HEAD에 대한
독립 검토, 가능한 고정 Astra 도구의 분석, User 결정의 GitHub 포인터가 필요하다.
Mac에 고정 도구가 없으면 그 한계를 표시하고 User의 직접 결정을 요청한다.

## 변경의 좁은 범위

기존 worker 종료 영수증이 사라진 실행에 한해, 재시작 전 저장한 attempt·binding·
요청·전체 작업 해시, 하드웨어 UUID의 해시와 macOS 커널의 `kern.bootsessionuuid`를
재시작 후 대조한다. 다른 Mac에 복사한 witness는 거절한다.
부트 식별자 변경과 커널의 부팅 시각이 기존 실행 및 witness 작성 이후라는
독립 확인을 함께 요구한다. witness의 SHA256을 User 결정에 고정하고 apply에
별도로 전달한다. 소유자 전용 파일도 소유자가 수정할 수 있으므로 파일 권한을
불변성이나 보호된 감사로 간주하지 않는다. 프로세스 이름, PID 부재, 모델의 완료
문구는 종료 증명으로 쓰지 않는다.

`engineering/tools/mac_recover_after_restart.py`의 `prepare`는 읽기 전용 DB 조회와
소유자 전용 단회 witness 저장만 수행한다. SQLite sidecar의 소유권을 검사하고,
WAL이 있는데 SHM이 없으면 읽기 전에도 거절한다. UNKNOWN이며 pause 요청이 기록된
실행만 대상으로 하고, 다른 미완료 작업이 있으면 거절한다. 원래 작업을 변경하지 않는다.

User 채택 후 명시적인 `apply`는 부트 변경을 먼저 확인하고, 기존 설치의 앱·plist·
프로세스 연결을 검사한다. 해당 서비스만 중지하고 서비스 잠금 아래에서 같은
증명을 재검사한 뒤 단일 DB 트랜잭션으로 해당 attempt를 `aborted`로 기록한다.
읽기 전용 역할의 checkout HEAD·청결과 원래 레포·범위 바인딩도 재검사한다.
작업은 `paused`이며 자동 재실행하지 않는다. 원래 계획·코드·로그·요청·호출 수를
보존한다. worker의 `receipt.json`을 만들거나 수정하지 않으며 모델 보고서를
계획·리뷰·완료로 채택하지 않는다. 서비스는 다시 시작한다.

같은 부트, 변경된 작업/요청, 늦은 영수증, 다른 미완료 작업, 재사용한 witness는
거절한다. `--force`나 임의 PID 종료, DB 초기화, 성공 승격 경로는 없다.
GitHub 결정 URL은 사람이 명시적으로 승인한 계약의 추적 포인터다. URL 문자열이나
댓글 문구를 자동 승인 또는 감사 PASS로 해석하지 않는다. CLI는 자동화에 등록하지 않는다.

## 운영 순서

1. 검토를 위해 재시작 전에 대상 실행의 witness를 준비한다. 작업은 변경하지 않는다.
2. 정확한 변경 HEAD의 검토·CI, witness SHA256 및 User 채택 결정을 기록한다.
3. User가 저장하지 않은 작업을 저장하고 Mac을 재시작한다.
4. 같은 Mac에서 결정 포인터와 witness를 지정해 명시적으로 apply한다.
5. 기존 목표를 다시 진행하려면 사용자가 선택한 같은 프로필로 resume한다.
   설치 검증용 fixture를 다시 시작할 경우 기존 기록을 보존하는 지원 cancel 이후
   정상 `--update`와 새로운 request ID를 사용한다.

이는 Mac의 단일 draft 작업 복구이며 VM/보호된 Fable의 UNKNOWN이나 writer 권한을
해제하지 않는다. 재시작 없는 복구와 성공 보고 복원은 이 후보에 포함되지 않는다.
