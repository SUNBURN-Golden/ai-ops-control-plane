# AIOPS Mac 0.3.1 실행 신뢰성 보완

사용자 요청: Grok을 통한 실제 자동개발을 평가하고, 운영에서 드러난 문제를 Mac 앱에 반영한다. 조사 결과와 실행 근거는 Mac 앱 PR #55의 평가 기록에 둔다. 이 문서는 작업별 실행 원장이나 보드의 대체물이 아니며, 구현된 경계와 남은 범위를 설명한다.

## 설계에 대한 반성

기존 설계는 단일 writer와 보호된 검토를 강조했지만, 사용자가 기대한 “한 번 맡기고 결과만 검수”를 위해 필요한 실행 준비, 오류 분류, 종료 관측과 완주 판정은 충분히 이어지지 않았다. 워크플로 성공, 세션 시작, PR 생성, 병합, 제품 완료를 별도로 측정해야 한다. 상태 보드가 갱신되지 않은 경우 실제 완료 수를 보드의 숫자만으로 추론할 수 없다.

실행 준비를 소스·설치·권한·실제 호출 가능 여부로 나누고, 각 단계에서 확인한 사실만 표시한다. Mac 앱은 시작 전 GitHub 인증과 선택된 실행 파일 존재를 새로 확인한다. 각 역할의 고정 명령을 예약 전에 구성하며, 실제 CLI 실행에서 드러난 로그인·모델·sandbox·권한 문제는 구체적인 설정 차단으로 기록한다. 설치됨을 모든 계정·모델의 사용 가능 증명으로 표시하지 않는다. 이 패치는 실제 공급자 인증을 무상 호출로 확인하는 새 기능이나 sudo 권한 부여를 추가하지 않는다.

## 실행과 재시도

| 관측 | 앱의 처리 |
|---|---|
| 동일 실행의 정상 종료 영수증 | 정확한 attempt/binding, 종료 코드, 프로세스 그룹 종료, 공급자·모델 일치를 확인한 뒤 결과 사용 |
| 오류와 성공 보고의 공존 또는 성공 보고와 비정상 종료 코드 | UNKNOWN으로 유지하고 예약을 해제하지 않음 |
| 종료 기록이 늦게 도착함 | UNKNOWN에서도 기존 영수증 관측만 허용; 검증되면 한 번 처리 |
| 종료 기록 없음·프로세스 그룹 미종료·읽기 역할의 코드 변경 | 단일 writer 예약 유지; 새 실행 금지; 최초 확인 필요 알림 |
| 로그인·모델·CLI·권한 오류 또는 구독 사용량 소진 | 확인을 한 번 요청하고 자동 반복 호출 중단 |
| 명시적인 일시 네트워크·속도 제한 장애 | 동일 공급자·모델·작업으로 5분부터 최대 1시간까지 간격을 늘려 재시도 |
| 분류되지 않은 같은 환경 오류 | 확인된 종료 후 두 번까지 자동 재시도; 세 번째에는 구체적인 환경 확인 요청 |
| 일반 구현·테스트·검토 실패 | 같은 개발자에게 지적을 반환; 임의 실패 횟수로 사용자에게 넘기지 않음 |

일반 개발에서 같은 지적·같은 HEAD가 반복되면 10초부터 최대 5분의 대기를 적용한다. HEAD나 지적이 바뀌면 대기가 초기화된다. 이는 작업을 포기하는 기준이 아니다. 작업 프로세스 시작 여부는 worker 영수증의 `provider_started`에 기록한다. 호출 요청 수는 과금량·유용한 작업 수·완료 수와 다르다.

상태 API와 UI에는 관측 시각, 실행 경과 시간, 세션 한도, 최근 출력 시각과 바이트 수, 다음 재시도 및 전역 UNKNOWN 소유권 차단을 표시한다. 로그 원문을 읽거나 API에 반환하지 않는다. 최근 출력은 작업의 유효한 진척을 증명하지 않는다. 다른 UNKNOWN 실행이 전체 로컬 실행을 막으면 재시도 시각보다 소유권 대기를 먼저 표시한다.

## 원래 프로그램 범위

준비한 checkout의 시작 SHA에서 schema-v1 `.aiops/program.json`을 읽어 Git blob, 노드 ID, 원래 spec, 의존성, 선언된 감사·사용자 병합·릴리스 설정과 기준 문서 포인터를 보존한다. 숫자 ID와 최대 256개 노드, 2 MiB 계획을 지원한다. 원래 명세의 반복 출력으로 모델을 낭비하지 않도록 앱이 각 계획 작업에 고정된 spec을 직접 붙인다. 계획이 모든 원본 노드를 한 번씩 포함하고 로컬 의존성을 유지하는지 검사한다. 프로그램을 작업 중 변경하거나 이미 커밋해 우회하는 변경도 감지한다.

계획 작성과 구현은 source, audit, qualification, release를 모두 같은 “완료”로 취급할 수 없다. 이 읽기는 범위·구조 검증이며 승인 URL을 보호된 승인으로 해석하지 않는다. 원래 명세 문자열을 붙였다고 구현의 의미적 준수를 증명하는 것도 아니다. 별도 감사·감리 세션이 시작 SHA의 원래 요구, 현재 코드와 검증 근거를 직접 비교한다. 감사 역할은 전체 계획의 모든 작업 ID를 반환해야 한다.

`depends_on_external` 등 지원하지 않는 확장 schema와 대기 승인 포인터는 거절한다. 별도 pending 카탈로그를 로컬 실행 범위로 승격하거나 전체 제품의 완료 분모에서 숨기지 않는다. 이 patch는 기존 보호 호스트의 plan admission, 노드별 task·PR·post-merge DONE, 고정 Fable A3 및 교차 레포 prerequisites를 Mac 네이티브 실행으로 이식한 것이 아니다. 앱의 하나의 checkout/draft 결과에는 이 차이가 남는다. 실제 이관은 기존 owner fencing과 새 호스트 qualification이 필요하다.

## 결과 검수의 현재성

개발자의 `complete`라도 미해결 finding·질문 또는 빈 검사 근거가 있으면 같은 작업의 보완으로 돌린다. 감사와 감리는 동일한 실제 HEAD에서 분리된 세션으로 수행한다. CI 대기 중 코드가 바뀌거나 최신 기준 브랜치가 달라지면 기존 검토를 폐기하고 재검증한다. 사용자가 검수 완료를 누를 때도 로컬 코드, 검토, 최신 기준 브랜치와 게시된 PR의 CI를 새로 확인한다.

이 앱은 검수용 draft를 제공한다. 검수 준비/검수 완료는 main 병합·운영 배포·병합 후 CI·보호된 노드 DONE이 아니다. 기존 VM의 비-KIX 저장소에 대한 병합 후 완료 함수는 별도 runtime 패치로 보완한다. 그 변경은 해당 runtime 소스 검토·감사·배포와 실제 merge-SHA CI 확인이 필요하며, Mac 앱 설치가 VM의 runtime을 활성화하지 않는다.

## 큰 프로그램과 서비스 시작

개별 명세·계획·리뷰는 유효해도 합친 작업 기록이 예전 JSON 읽기 한도인 4 MiB를 넘을 수 있었다. 작업 기록은 별도 16 MiB 한도로 읽고 저장 전에 검사한다. 일반 데이터에는 15 MiB까지 허용하고 나머지는 차단 상태와 종료 관측을 기록할 공간으로 남긴다. 초과 저장은 DB를 변경하지 않는다. 원본 명세와 계획을 잘라내어 성공시키지 않는다.

모든 공급자의 결과는 공통 2 MiB 한도와 필드별 크기·항목 수 검사를 통과한다. worker 요청은 별도 32 MiB 한도로 읽으며 JSON 이스케이프까지 포함한 실제 직렬화 크기를 실행 예약 전에 확인한다. 유효한 4 MiB 초과 작업의 저장·중복 조회·DB 재개와 8 MiB worker 요청을 실제 임시 파일·가짜 CLI subprocess로 검증한다.

상태 API는 작업 제목·수용 기준·현재 검증 HEAD·진행 관측을 반환한다. 원본 명세, 상세 작업 지시, 전체 리뷰 보고서를 반복 전송하지 않는다. 원본은 DB에 보존한다. 앱 최초 시작은 CLI 설치만 탐지하고 버전·네트워크 로그인 검사는 기다리지 않는다. 로그인은 확인 전으로 표시하고, 새 작업을 시작할 때 GitHub 인증을 다시 검사한다.

초기화·포트 바인딩·endpoint 기록 실패 시 DB·서버·서비스 잠금을 해제한다. 종료 중 기존 엔진 단계가 아직 실행된다면 해당 단계가 끝날 때까지 잠금을 유지한다. 봇의 HTTP 클라이언트는 환경의 프록시 설정을 무시하고 loopback에 직접 연결한다.

## 설치와 업데이트

`Install.command --update`는 기존 앱·LaunchAgent·데이터 디렉터리 연결을 검사한 뒤 수행한다. 작업이 완료·취소되지 않았거나 종료 예약이 남으면 서비스를 중단하지 않고 거절한다. 서비스 중지 후 잠금을 확보하고 읽기 전용 DB로 다시 검사하여 그 사이 들어온 작업도 보존한다. 교체는 staging에서 준비하며 시작 실패 시 이전 앱과 설정을 되돌린다. 부분 시작된 새 서비스가 이미 작업을 예약했으면 자동 제거 대신 소유권을 보존한다. 사용자 데이터·계정 토큰을 지우거나 복구 UI·패키지를 추가하지 않는다.

## 검증과 실제 적용

회귀 검사는 실제 임시 Git 저장소와 CLI subprocess를 사용해 시작·종료·에러 분류·범위 보존을 확인하고, 로컬 HTTP로 소유자와 봇 권한을 구분한다. 늦은 영수증, 모순된 완료, 계속되는 일반 개발 실패, 고정 설정의 일시 장애, 최신 기준/CI 변경을 재현한다. source 동료 검토는 보호된 Fable A3 영수증으로 기록하지 않는다.

macOS의 LaunchAgent·caffeinate·Keychain·sandbox·실제 CLI 계정과 기존 Grok owner 이관은 실제 Mac에서 확인해야 한다. 설치 소스 후보를 갱신했다고 이미 설치된 앱이나 VM 실행기가 업데이트되지는 않는다. 기본 `Install.command`는 기존 설치를 덮어쓰지 않으며 명시적인 `--update`가 필요하다. `launchctl print`의 출력 형태와 native 서비스 동작은 실제 Mac 검증 항목이다. 실제 계정의 end-to-end 검증 없이 무인 완주나 모든 공급자의 준비 완료를 주장하지 않는다.
