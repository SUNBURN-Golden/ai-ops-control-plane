## HR-D1 — 2026-10-01

- 결정자: User 박준태.
- 출처: 이 PR을 작성한 ChatGPT 대화의 2026-10-01 13:55:08 KST User 메시지. User는 아래 네 요구사항을 인용한 뒤 「이게 좋을듯」이라고 답했다. 접근 가능한 외부 대화 URL은 제공되지 않았으며 임의의 메시지 URL/ID를 만들지 않는다.
- 요구사항 원문:
  1. **설치 절차를 코드로 보관한다.** 승인된 버전과 해시를 고정해서 같은 설치를 재현한다.
  2. **AIOPS 명령 앞에 복구 절차를 붙인다.** 설치 확인 → 누락분 복원 → 버전·권한·인증 확인 → 작업 실행.
  3. **작업 상태도 보존한다.** 실행 ID, 완료 기록, 중복실행 방지, 사용량·과금 제한 상태까지 유지해야 한다. 설치만 복구하고 이 기록이 초기화되면 문제가 다시 생겨.
  4. **복구 후 진행 중 작업을 무조건 재실행하지 않는다.** 기존 실행 상태를 확인하고, 확인할 수 없으면 멈추도록 한다.
- 선택 범위: 위 네 요구사항에 따라 검토 가능한 복구 설계안을 준비한다. 구체 설계는 [설계 제안](HOST_REPLACEMENT_RECOVERY_DESIGN.md)에 있다.
- 승인으로 간주하지 않는 사항: 구체 저장 형식·freshness witness backend·신뢰 근거·호스트 epoch 전환의 채택, 재부팅 초기화 VM 금지의 예외, unattended root bootstrap, 새로운 sudo/계정/자격증명, source pin 변경, 과금 설정 변경, 원장 초기화, 미확인 실행의 재시도, 병합·설치·활성화.
- 기록의 효력: 본 문서와 이를 담은 PR 커밋의 경로/절 포인터는 방향 선택의 저장소 내 근거다. 작성자가 옮겨 적은 기록이며 GitHub 작성 계정만으로 실제 User 신원을 암호학적으로 증명하지 않는다. 보호된 승인 reader나 host authorization의 입력을 대신하지 않는다.
- 적용 조건: 독립 exact-HEAD A3, 필요한 명시적 User 설계 채택, 실제 호스트 qualification과 기존 설치·activation 절차. PR #47의 PA-1은 별도 program Astra 정책 결정이며 HR-D1의 root/복구 권한으로 전용하지 않는다.
